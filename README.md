# 电商数据库设计与查询项目

## 项目简介

模拟真实电商业务场景，完成从数据库表结构设计到复杂业务查询的完整实战：7 张表（用户、分类、商品、地址、订单、订单详情、支付）+ 10 道分难度业务查询题（基础 / 进阶 / 综合）。

## 技术栈

- MySQL（含主外键、唯一约束、CHECK、默认值、注释等完整约束设计）

## 数据库设计

| 表名 | 说明 | 设计要点 |
| --- | --- | --- |
| users | 用户表 | 用户名/手机号唯一约束，状态字段软禁用 |
| categories | 商品分类表 | parent_id 自关联外键，支持多级分类树 |
| products | 商品表 | 分类外键、上下架状态 |
| user_addresses | 收货地址表 | (user_id, is_default) 唯一约束，保证每用户仅一个默认地址 |
| orders | 订单表 | 订单状态流转（待支付→已支付→已发货→已完成） |
| order_items | 订单详情表 | 数量 CHECK 约束，记录下单时单价快照 |
| payments | 支付表 | order_id 唯一，一单一支付 |

## 功能特性

- ✅ **完整建表 SQL**：含主键、外键、唯一约束、CHECK、默认值、字段注释
- ✅ **测试数据**：覆盖多级分类、多用户、多订单场景，开箱即用
- ✅ **10 道业务查询**：从单表条件查询到多表嵌套子查询，难度递进
  - 基础：订单查询、分类统计、地址排序、支付记录筛选、销量 Top3
  - 进阶：用户消费画像（客单价/首末单时间）、反向筛选（未购买某类的用户）、订单明细小计
  - 综合：每日经营报表（订单量/销售额/支付金额）、高价值用户购买明细
